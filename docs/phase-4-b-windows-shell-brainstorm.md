## 1. P4-B 要交付什么

P4-B 的目标是把已经完成的 Python Agent Host 装进一个真正的 Windows 桌面宿主，让后续财务、财富管理和其他 AI 应用模块可以使用同一套窗口、导航、Agent 面板、毛毛、主题、设置和后台生命周期。

P4-B 完成时，用户应当能实际看到并操作：

1. 一个 Windows 主窗口；
2. 左侧模块导航；
3. 中间模块工作区；
4. 右侧可展开的模块 Agent 面板；
5. 一个独立但属于同一 Host 的毛毛窗口；
6. Windows 托盘入口；
7. 主题、隐私、毛毛和关闭行为设置；
8. 后端启动中、在线、离线、恢复和失败状态；
9. 从后端模块注册表与桌面内置 UI 注册表的交集生成导航；
10. 主窗口关闭后按设置隐藏到托盘、询问或退出。

P4-B 不假装已经完成财务业务页面。真实财务驾驶舱、账本图表、候选确认和写账闭环属于 P4-C；财富管理的应急金、储蓄与资产视图属于 P4-D。

## 2. 已确认的主窗口布局

用户此前提供的两张效果图已经确定了桌面产品的视觉与信息架构基线，不再把“默认首页显示什么”作为待决问题：

- 第一张是日常财务模块的目标界面：左侧导航、中间“我的财务驾驶舱”、右侧财务助手，底部显示同一个毛毛的日常管钱形态；
- 第二张是财富管理中的“投资与学习”视图参考：左侧导航、中间持仓/配置/风险与学习内容、右侧投资助手，底部显示同一个毛毛的财富管理形态；
- 两张图中的数值都是演示数据，不能直接变成产品默认事实；布局、层级、信息密度和模块切换关系是已确认设计；
- 最终产品统一使用 `Maris` 作为应用名、`毛毛` 作为桌宠名；“投资”是财富管理模块中的子视图，财富管理还包括应急金、储蓄、保障、现金管理、资产配置和长期目标。

首版采用“左侧导航 + 中间工作区 + 右侧 Agent”的桌面工作台结构：

```text
┌──────────────────────────────────────────────────────────────┐
│ Maris                         后端在线   隐私模式   设置       │
├──────────────┬──────────────────────────────┬────────────────┤
│ 模块导航      │ 当前模块工作区                 │ 模块 Agent      │
│              │                              │                │
│ ● 日常财务    │ P4-B：模块欢迎页/状态页         │ 毛毛·日常管钱    │
│ ○ 财富管理    │ P4-C：财务驾驶舱               │ 快捷问题         │
│              │ P4-D：财富管理视图              │ 会话/运行状态     │
│ ───────────  │                              │ 待确认动作       │
│ 记忆中心      │                              │                │
│ 设置          │                              │                │
├──────────────┴──────────────────────────────┴────────────────┤
│ request ID / 连接状态 / 当前 Profile / 安全提示               │
└──────────────────────────────────────────────────────────────┘
```

推荐理由：

- 中间区域保留给数据可视化和业务操作，不被聊天占满；
- Agent 始终与当前模块绑定，用户能看出它正在以哪个身份工作；
- 右侧面板可以折叠，查看图表或账本时获得更大的空间；
- 后续增加模块时只注册导航、路由、Agent Profile 和毛毛形态，不重写 Shell；
- 微信仍是日常快速输入渠道，桌面端更适合看数据、管理记录和深入对话。

主窗口不会在 P4-B 显示伪造余额、模拟股票涨跌或静态“智能建议”。业务区域只显示明确标记的模块欢迎页、能力状态和进入后续切片的占位说明。

## 3. 模块与 Agent 的关系

Maris 只有一个桌面 Host，但每个模块可以有不同的逻辑 Agent Profile：

| 模块 | Agent Profile | 主要职责 | P4-B 可见状态 |
| --- | --- | --- | --- |
| 日常财务 | `daily_finance` | 记账、查询、纠错、消费前评估 | 已注册，可显示快捷问题和连接状态 |
| 财富管理 | `wealth_management` | 应急金、储蓄、保障、资产配置、长期目标；投资只是子能力 | 首版显示为后续模块或受控占位，不接行情和股票推荐 |
| 后续 AI 应用 | 各自 Profile | 按模块合同加入工具、记忆和 UI | Shell 不写模块 ID 分支，通过注册表接入 |

切换模块时发生的是确定性的 UI/Profile 切换，不调用模型、不写财务数据。Agent 只有在用户发送消息或触发明确动作时才运行。

模块专属记忆与共享记忆继续遵守 P4-A 地基：

- 当前模块只读获准的专属命名空间；
- 共享记忆必须经过确认；
- 账目、余额、预算、持仓和行情不是记忆，必须通过领域工具查询；
- 页面切换不会把一个模块的私有对话自动交给另一个模块；
- 用户以后可在记忆中心查看、确认、作废和删除记忆。

## 4. 毛毛的首版定义

毛毛只有一个，不是第二个 Agent。它是同一个 Host 和当前模块 Agent 的低打扰入口。

毛毛的状态分为两个维度：

1. **主形态**：随模块变化。
   - 日常财务：日常管钱形态；
   - 财富管理：财富管理形态；
   - 后续模块：由模块贡献自己的形态映射。
2. **子状态**：表示当前运行状态。
   - `idle`
   - `listening`
   - `thinking`
   - `tool`
   - `needs_confirmation`
   - `error`
   - `offline`

首版采用“简化透明窗口 + Tray”：

- 可拖动；
- 可选置顶；
- 记住位置、大小和显示器；
- 拔掉显示器或分辨率变化后自动夹回可见区域；
- 全屏应用时默认隐藏；
- 隐私模式下不在气泡显示金额、账户和消息正文；
- 点击毛毛打开或聚焦主窗口，并展开当前模块 Agent 面板；
- 透明窗口不兼容时降级为普通迷你窗口，功能合同不变。

P4-B 不制作复杂动画、美术皮肤、自动情绪系统或主动财务提醒。首版可以使用两种容易辨认但明显属于同一角色的静态/轻量状态素材，验证模块映射和生命周期；美术深化另立任务。

## 5. 本地单主人启动方式

当前产品范围是单机、单主人、本地数据库，因此 P4-B 不制作公众注册页面，也不要求用户每次输入账号密码。

推荐启动流程：

```text
用户启动 Maris
  → Electron main 启动或连接本机 Python Host
  → 等待带启动 nonce 的 readiness
  → main 恢复本机 bootstrap owner 的安全设备会话
  → renderer 取得短时访问状态，不持久保存 refresh token
  → 加载 /modules
  → 计算后端启用模块与桌面内置 UI 的交集
  → 打开上次模块或日常财务首页
```

将来如果需要保护共享电脑，可以增加“应用锁”或 Windows Hello；这和公众账号注册是不同需求，不在 P4-B 首版实现。

## 6. 后端生命周期

P4-B 推荐同时支持两种开发方式：

| 模式 | 用途 | 谁负责停止后端 |
| --- | --- | --- |
| 桌面托管 | 普通使用；Electron main 启动 Python Host | 只由启动它的同一桌面实例停止 |
| 连接开发后端 | 调试；开发者手工启动 FastAPI | Electron 不取得所有权，也不停止它 |

`BackendSupervisor` 必须记录 PID 和启动 nonce，使用随机 loopback 端口，并区分 `starting / online / offline / recovering / failed`。健康检查不能代替 readiness；错误 nonce、错误 origin、过期 token或非 loopback 请求均拒绝。

后端崩溃时：

- Shell 保持可见；
- 毛毛切到 `offline`；
- 未发送的文本和原 `client_event_id` 保留；
- 自动重启次数和退避有上限；
- 恢复后继续使用同一个 ID，避免生成重复候选；
- 用户能打开诊断信息，但看不到内部路径、SQL、token 或堆栈正文。

## 7. 已采用的产品默认值

除非后续实际设备验证发现问题，P4-B 采用以下默认值：

| 项目 | 默认值 |
| --- | --- |
| 关闭主窗口 | 隐藏到 Tray，并只在第一次解释一次 |
| 关闭策略设置 | 隐藏到 Tray / 每次询问 / 退出 |
| 毛毛 | 简化透明窗口 + Tray，可安全降级普通迷你窗口 |
| 开机启动 | 默认关闭，用户显式开启 |
| 毛毛置顶 | 默认关闭，可在设置中开启 |
| 隐私模式 | 可快速切换；隐藏金额和敏感气泡 |
| 全屏行为 | 默认隐藏毛毛 |
| 主题 | system / light / dark，并保留 high-contrast 与 reduced-motion |
| Agent 输出 | P4-B 不把 token 流式输出作为门槛；最终状态可恢复 |
| 真实数据 | P4-B 不导入真实个人财务数据 |
| 登录界面 | 不做公众注册和常规账号登录；使用本地 owner 会话 |

## 10. 已确认的视觉方向

首版视觉应当像一个安静的个人驾驶舱，而不是交易软件或聊天软件的复制品：

- 主窗口以信息阅读和数据区域为中心；
- AI 面板存在但可折叠，不永久抢占注意力；
- 毛毛承担陪伴感和快速入口，不用夸张动画干扰学习；
- 日常财务形态使用偏生活、温暖的视觉提示；
- 财富管理形态使用更沉稳、规划感更强的视觉提示；
- 两种形态保留相同轮廓、脸部或核心标志，确保能看出是同一个毛毛；
- 收入、支出、成功、风险、行情涨跌使用独立语义颜色，避免含义混乱。

正式采用“左侧模块导航 + 中间驾驶舱 + 右侧 Agent + 外部毛毛”为 P4-B 视觉基线。日常财务和投资与学习两张效果图分别作为模块状态参考；后续不再重新询问默认首页、三栏布局或 Agent 是否随模块切换。P4-B 只实现 Shell 与状态映射，真实财务闭环留在 P4-C，真实财富数据与计算仍留在 P4-D。

## 11. 下一轮需要冻结的技术问题

这些问题交给技术顾问比较方案后由总控冻结，不在头脑风暴阶段凭感觉选依赖：

1. Electron、Node、React、TypeScript 的精确版本与锁定策略；
2. Vite 或其他桌面构建方案；
3. React Router 或其他路由方案；
4. 本地 UI 状态管理方案；
5. OpenAPI TypeScript 生成器；
6. IPC allowlist 和错误合同；
7. BackendSupervisor readiness、超时、退避和进程所有权合同；
8. 设备设置 JSON schema、迁移和原子写入；
9. Electron 自动化测试与 Windows 手工验收工具；
10. 毛毛透明窗口的 GPU、焦点、DPI 和无障碍降级标准。

在这些问题冻结前，不安装 Electron/React 依赖，不启动执行智能体，也不把视觉占位页面误报为财务驾驶舱完成。
