# 开发与学习路线 v0.3

状态：阶段 0 核心纵向切片已完成并通过真实微信验收；当前进入阶段 1 数据底座设计。以能力验收推进，不设未经讨论的固定周数。

## 两条学习线

财务 Agent 在产品内教授预算和投资等知识。工程教学由用户已指定的“技术顾问”任务负责，依据实际提交、代码与验证结果解释，并在实现前提供选型咨询。技术顾问负责教学规划，按需要调度教学代码检查、测试、阅读搜索等子任务，并核对交付结果。

头脑风暴任务负责与用户沟通、维护总计划、协调各角色；技术顾问负责方案比较、教学顺序、知识讲解、练习与教学子任务管理；执行智能体负责实现、自测、集成及执行子任务管理；测试智能体负责独立验证、边界检查和限定范围的结构优化。教学代码检查与测试用于验证练习，练习进入项目时仍需项目验证。任务之间通过仓库文档和明确交接同步，不假设共享全部聊天记录。具体边界见 [任务分工与进度](project-coordination.md)。

终端范围已经调整为 Windows 桌面应用与手机微信聊天。前端学习集中在 TypeScript、React 和 Electron，手机端学习渠道适配、消息协议与可靠投递；不安排 Android 应用开发课程。

## 每项功能开始前的技术说明

必须说明：用户问题、当前系统位置、拟用技术、至少一个有意义的替代方案、选型理由、额外学习内容、验收方式。没有实质替代价值的小改动不必制造多个方案。

例如“补充金额后继续评估”：先用显式状态机说明需要保存什么，再比较继续维护 Python 状态机与引入 LangGraph 的代码复杂度、恢复能力和运行成本。

重要选择在实现前给出具体比较；用户已经表达的方向无需反复请求许可。新的付费资源与外部账号接入到实际需要时再处理。

## 每项功能完成后的交付

1. 实际改动与状态，明确已实现、未实现和模拟部分。
2. 实际文件路径与函数/类型入口；尚未存在的路径必须标为规划。
3. 输入 → 接口 → Agent/工具 → 业务逻辑 → 数据库 → UI 的实际数据流。
4. 运行方式、相关验证结果和已知限制，不把未运行的检查写成通过。
5. 一项用户可以亲手修改或调试的小练习。
6. 更新教学交接记录和必要的架构决定。

学习状态建议使用“未接触、已讲解、能解释、能修改、能独立排错”。功能被 Codex 实现不自动意味着用户已掌握，练习完成后也只记录真实证据。

## 资料使用

以 [Hugging Face Agents Course](https://huggingface.co/learn/agents-course/unit0/introduction) 的 Agent 基础、工具和框架内容作为课程参考，按项目需要选读。课程覆盖多个框架，不意味着项目必须全部安装。

具体实现以当前官方技术文档为准；工程博客用于了解经验与取舍，并核对其版本和实验条件。用户提到的知识点图片目前未收到，收到后再映射进路线。

代码学习入口：[DeepSeek 工具调用](https://api-docs.deepseek.com/guides/tool_calls/)、[FastAPI](https://fastapi.tiangolo.com/features/)、[SQLAlchemy](https://docs.sqlalchemy.org/en/20/orm/quickstart.html)、[React](https://react.dev/learn)、[LangGraph 暂停恢复](https://docs.langchain.com/oss/python/langgraph/interrupts)。

## 后续选修

MCP/FastMCP 与 Skills 围绕确实需要复用的外部工具和稳定任务加入。多 Agent、复杂 RAG、微调、蒸馏和强化学习由实际问题及评测证据决定。若希望财务 Agent 自主生成并运行分析代码，另做沙箱执行、数据授权和结果校验专题。

长期目标以可展示能力衡量：能解释设计、修改功能、定位失败、验证改动并部署维护。完成一个项目本身不等于自动达到全部工程岗位要求。
