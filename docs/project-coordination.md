# 任务分工与进度

## 用户确定的职责

项目采用四类智能体角色。名为“头脑风暴”的任务保留用户指定的总协调职责：与用户聊天、梳理方向、控制总进展、制定和更新计划、协调其他智能体。用户已将工程教学任务命名为“技术顾问”，负责教学规划与教学子任务调度。本文供各任务共享，角色名称不随阅读本文的对话改变。

| 角色 | 负责内容 | 交付内容 |
| --- | --- | --- |
| 用户 | 产品目标、个人偏好、重要方案取舍、使用反馈与学习 | 明确目标、反馈和需要调整的方向 |
| 头脑风暴 | 需求澄清、方案讨论、优先级、里程碑、跨角色依赖协调、交付核对 | 总计划、任务说明、进度、待决策项、下一步安排 |
| 技术顾问（教学统筹） | 实现前提供选型与架构建议；规划教学任务；解释原理和实际代码；调度教学代码检查、测试、资料检索等子任务；指导练习与记录掌握情况 | 教学计划、方案比较、讲解、练习、检查与测试反馈、阅读资料、学习证据和待理解问题 |
| 执行智能体 | 代码实现、项目环境、调试、自测、修复、集成；管理执行子任务 | 实际代码、运行方式、自测证据、子任务状态、限制与教学交接 |
| 测试智能体 | 独立测试设计与执行、边界检查、回归验证、代码结构审查与限定范围的优化 | 可复现缺陷、测试与场景集、验证报告、结构优化改动和剩余风险 |

头脑风暴任务可以维护项目文档、检查代码与验证结果、做必要的只读调查。具体业务实现交给执行智能体。技术顾问同时服务用户学习和项目技术决策；测试角色独立于执行角色提供结论，但不免除执行者的自测责任。

## 开发、自测与独立验收的边界

“执行智能体自测”和“测试智能体测试”不是重复工作，二者承担不同责任：

| 工作 | 执行智能体 | 测试智能体 | 技术顾问 | 头脑风暴总控 |
| --- | --- | --- | --- | --- |
| 实现业务代码 | 唯一负责人 | 禁止，除非总控另行划定修复范围 | 禁止 | 禁止 |
| 编写执行方单元/组件测试 | 必须；与实现一同交付 | 只读参考，不把它当独立证据 | 可只读讲解 | 只读核对 |
| 运行格式、类型、单元、组件和最小冒烟检查 | 必须；证明交付达到可测试状态 | 在最终回归中统一复跑并与独立案例分开统计 | 可以为教学复跑，不作验收结论 | 默认只核对命令、结果、快照和交付物；有矛盾时才定向复现 |
| 设计独立验收矩阵 | 不得代替测试智能体 | 唯一负责人 | 可提出风险，不修改矩阵 | 冻结验收口径 |
| 编写独立边界、并发、故障和回归用例 | 禁止修改测试方专属路径 | 唯一负责人 | 禁止 | 禁止 |
| 修复测试发现的产品缺陷 | 接到返修任务后负责 | 提交最小复现；未经分配不改产品代码 | 解释原理和方案影响 | 决定返修范围与负责人 |
| 给出独立通过/失败结论 | 无权；自测通过只能进入 `review` | 唯一负责人 | 无权 | 根据冻结标准和独立证据作项目验收 |

执行方必须自测，否则测试方收到的是不可运行的半成品；测试方必须独立验证，否则只是重复执行者自己的判断。两者可以运行部分相同命令，但证据名称、用例所有权和结论权限必须分开记录。

每个开发任务都按下面的交接顺序推进：

1. 总控冻结接口、验收标准和文件所有权。
2. 执行智能体实现代码，并编写执行方测试；自测通过后提交不可变快照和 `review`，停止继续扩展功能。
3. 测试智能体在该快照上直接运行独立矩阵，并在一次最终回归中同时覆盖执行方测试；发现缺陷只提交复现和结论。
4. 总控把缺陷明确返还执行智能体；执行方修复并重跑自测。
5. 测试智能体独立回归；总控核对快照、报告、失败项和未验证项后标记 `complete`。快照未变化且证据一致时，总控不再重复全量测试。

## Git 与发布流程

Git 写操作集中由头脑风暴总控负责。执行、测试、技术顾问和所有子智能体只交付工作区文件、验证结果及快照摘要，不执行暂存、提交、分支、合并、推送或 PR 操作。

每个任务或里程碑完成独立验证并由总控验收为 `complete` 后，总控按实际验收范围创建本地提交。首个大版本必须由用户明确宣布；此前默认只保留本地提交，用户另行要求时可以建立远端保护性检查点。保护性检查点不算大版本，也不触发 PR-only 流程。只有首个正式大版本发布以后，后续工作才统一采用“独立分支 → 本地提交 → 推送分支 → GitHub PR → 验收后合并”，全流程仍由总控执行 Git 写操作。

## 流水线效率规则

- 总控的交付核对只确认文件是否齐全、快照是否一致、执行方是否自测、是否存在未披露阻塞，默认不做第二轮完整代码审查或全量回归。
- 测试智能体是唯一完整独立验收方。执行方测试与独立测试在测试方最终回归中统一运行一次，并在报告中分开统计。
- 总控仅在摘要不一致、测试报告互相矛盾、严重缺陷、环境差异或验收口径争议时运行定向复现。
- 接口冻结后，测试准备可以与实现并行；实现提交稳定快照后，测试方直接绑定该快照执行，减少等待。
- 技术顾问可在稳定快照形成后与 C4 并行准备只读教学材料，但正式教学结论要吸收最终测试结果。

禁止执行智能体修改 `tests/independent/` 或独立测试报告，也禁止测试智能体在没有明确返修授权时修改产品实现。任务 Prompt 必须分别列出“执行方自测范围”“独立验收范围”和“谁有权作结论”。

## 教学子任务

技术顾问在用户及头脑风暴确定的项目方向内，主动安排学习顺序、练习、代码检查、测试和必要理论补齐，并根据反馈调整难度。常规教学拆分与子智能体调度由技术顾问负责，用户无需逐个安排。

- 教学代码检查与测试子智能体：检查用户练习或指定代码，按学习目标验证正常、异常与边界行为，提供准确代码位置、复现步骤、预期与实际结果；默认先反馈问题和提示，用户要求直接修复时承接该要求。
- 阅读与搜索子智能体：围绕具体知识缺口查找官方文档、标准或原始论文，核对版本与适用范围，交付少量必读内容、阅读顺序、关键解释和理解检查题。
- 其他教学子任务：需要时安排示例实验、调试分析、架构图解或复习材料；技术顾问负责核对结果、统一讲解并记录学习证据。

上述子任务按实际需要创建或复用，不代表它们已全部启动。教学代码检查与测试服务用户学习；项目测试智能体仍负责独立的项目验收。练习进入主项目时，由执行智能体集成，并按项目要求接受独立验证。

每次派发明确目标、输入代码版本或快照、依赖、可读写范围、交付物与验收标准。教学改动采用独立实验或协调后的文件范围，避免与执行任务并发修改同一文件。跨角色依赖和影响项目范围的变化交回头脑风暴协调。详细流程见 [技术顾问与教学交接](teaching-handoff.md)。

## 执行子任务

执行智能体根据具体里程碑按需安排执行子智能体，例如后端、微信桥接、桌面界面和数据迁移。每个子任务须有明确输入、修改范围、接口、验收标准和结束条件；无需将这些例子全部创建为长期角色。

执行智能体负责子任务间的接口一致性、冲突处理和集成，并向头脑风暴任务统一汇报。测试智能体与执行智能体作为同级质量协作角色，不由执行者代替其作出独立测试结论。

## 测试与结构优化的边界

- 测试依据需求与业务规则设计，覆盖合理的正常、异常、边界与恢复场景，避免仅复制实现逻辑。
- 财务重点包括金额精度、退款与转账口径、重复写入、预算版本；Agent 重点包括工具选择、坏参数、权限、超时、恢复与证据；微信重点包括重复消息、身份绑定和提醒送达。
- 测试智能体可以在划定的文件范围或独立分支中进行结构优化，说明问题、改动理由、行为兼容性和验证证据。
- 执行与测试不能同时修改同一模块。涉及该模块的优化先协调交接时间或隔离改动，再由执行智能体集成。
- 行为变更和较大架构调整先交技术顾问分析，由头脑风暴任务纳入计划并与用户讨论。常规可逆修复在已分配范围内推进。
- 执行智能体或测试智能体修复缺陷后都要重新验证；不能把结构更整齐视为行为正确或性能改善的证据。

## 协调方法

1. 将需求整理成有边界的任务：目标、输入、依赖、修改范围、技术提案、交付物和验收标准。
2. 技术顾问在开始实现前说明涉及的技术与有意义的替代方案，头脑风暴任务汇总取舍并承接已确定的选择。
3. 由执行智能体落实开发并管理有边界的执行子任务；测试智能体可以同时根据稳定的需求准备测试，有依赖的工作按顺序推进。
4. 明确文件归属或隔离工作目录；避免多个执行者同时修改同一位置。
5. 根据实际反馈跟踪完成项、正在进行项和阻塞项，不能把计划派发视为完成。
6. 执行者完成自测与集成后，测试智能体开展独立验证，缺陷回到执行/修复流程；头脑风暴任务核对验收证据后标记完成。
7. 汇总技术交接给技术顾问，由其规划教学、调度教学子任务、核对用户练习并反馈后续知识缺口；分别记录项目进度和用户学习进度。
8. 某项工作连续错过两个检查点且没有进展时，总控要求相关智能体在安全位置停止，保留现场并报告卡点、错误、已尝试方案和需要共同决定的问题；问题解决后再恢复或重新派发。
9. 每个活动任务只能有一个执行负责人。测试可以并行准备和只读验收，但安装、登录、服务启停、部署、外部写入及实现修改必须由控制文件中指定的负责人执行；交接先停旧负责人，再启新负责人。

不默认所有任务共享完整聊天上下文。交接应指定项目文档、实际代码版本和本次任务范围。角色设计不等于任务已启动；独立任务或子智能体只有在实际建立或接入后才登记为已就位。

每个执行或测试任务的交接至少包含：目标、负责人、输入版本、依赖、可修改范围、验收标准、交付物、状态和实际验证结果。

所有角色按 [智能体进度台账规则](coordination/README.md) 更新自己的状态文件；头脑风暴智能体核查交付证据并维护 [项目进度总览](coordination/overview.md)。共享文档没有接单或证据记录时，总控必须使用“未核实”或“待接单”，不能推断任务已经开始或结束。

运行中的智能体还要记录当前步骤、开始时间、最近有效进展、心跳、下一检查点、等待对象和可观察的进程/会话。父智能体并行调度多个子任务时，对每个子任务分别汇总这些字段，不能只记录“运行中”。总控据此识别正常耗时、等待依赖、反复重试和疑似停滞，详细判定见台账规则。

## 进度沟通格式

向用户优先说明：当前阶段、已完成且有证据的结果、正在推进的任务、阻塞及解决安排、需要用户参与的具体事项、下一步。常规工程协调由统筹任务处理；产品目标和重大方案取舍与用户讨论。
