## 1. 用户实际使用方式

日常账单不要求制作 Markdown 文件。当前输入渠道按下面定位：

| 渠道 | 主要用途 | 示例 |
| --- | --- | --- |
| 微信消息 | 日常最常用的记账、查询、消费前评估和纠错入口 | “午饭 18 元”“刚才那笔不是餐饮，是社团活动” |
| 桌面聊天 | 与微信共用 Agent 和账本；适合长问题、查看依据和继续追问 | “总结我最近七天的餐饮开支” |
| 桌面快捷表单 | Agent 无法可靠理解、需要精确修改或批量核对时的备用入口 | 修改金额、分类、时间、账户 |
| Markdown 活动导入 | 批量建立或更新常见活动模板和参考金额，不是逐笔账单 | 食堂午饭 12～20 元、社团活动 0～50 元 |
| 账单文件导入（后续） | 导入微信支付、支付宝或银行提供的 CSV/Excel 账单 | 对账、发现漏记和重复记录 |
| 图片/OCR（后续） | 识别票据或截图并形成待确认候选 | 小票、支付截图 |

微信与桌面聊天最终调用同一套 Python Agent 工具和数据库。聊天消息本身不是账目；模型先把消息理解为结构化候选，确定性程序校验金额、权限、幂等和事务，用户确认后才写入账本。

## 2. 最终桌面产品不是三选一

此前的“活动导入界面、聊天界面、财务仪表盘”不是三个互斥产品，而是同一个桌面应用的不同区域：

1. **财务驾驶舱**回答“我现在怎么样”。展示余额、月度支出、预算使用、目标进度、可自由支配金额和近期异常。
2. **AI 助手**回答“为什么”和“接下来怎么办”。可以查询账本工具、解释图表、记录消费、评估消费意图、教授理财知识。
3. **资料管理**维护“系统知道什么”。管理活动模板、预算、目标、账户、分类和 Markdown 批量导入。
4. **迷你助手/桌面宠物**负责低打扰入口。它显示简短状态、提醒和异常；点击后展开与主应用共享的聊天。
5. **投资区**回答持仓表现、市场资料和学习问题。它使用独立行情/搜索工具，不允许模型凭记忆编造价格，也不直接替用户下单。
6. **账本管理**让用户核对 Agent 导入结果。提供图表、交易列表、筛选、详情、来源、确认记录和可审计纠错，不能要求用户盲信 LLM。
7. **记忆中心**让用户查看、确认、修改和删除 Agent 使用的稳定偏好与目标；记忆不保存账本事实，不代替关系数据库。

## 4. “还剩 10 元，可以享受两瓶冰红茶”怎样实现

这个结果不能由 LLM 随口计算，需要两个确定性数据源：

1. **可自由支配金额**：由账本、预算、必须预留、目标预留和安全缓冲计算。
2. **参考享受项目**：来自活动模板或用户维护的商品参考价，例如“1L 冰红茶 5 元”。

概念公式：

```text
可自由支配金额
= 当前可用资金
+ 规划期内可信收入
- 必要生活预留
- 已知固定支出
- 安全缓冲
- 已承诺目标储蓄/投资预留
- 已发生但尚未计入计划的支出
```

具体口径需要在规划引擎阶段冻结，不能把公式直接当作当前已实现能力。若冰红茶参考价是精确 5 元，10 元可以显示约 2 瓶；若参考价是 4～6 元，应显示“约 1～2 瓶”，不能用平均价伪装成确定事实。

LLM 的作用是解释：为什么只剩 10 元、哪个预算占用了资金、改变某个计划会怎样。除法、预算扣减和范围换算由程序完成。

在确定上限后，Agent 可以结合经过用户确认的偏好给出多个“怎么花”的方案，而不是只换算商品数量。例如：

- 全部用于当下享受：两瓶参考价 5 元的饮料；
- 平衡方案：5 元买一瓶饮料，5 元保留到明天；
- 兴趣试错：选择一个不超过 10 元的低成本体验；
- 目标优先：今天不消费，把 10 元并入当前目标。

程序先验证每个方案没有超过允许金额；LLM 再解释不同方案的体验、机会成本和与目标的关系。“不花”必须始终是合法选项。涉及实时价格时，方案要使用带来源和时间的搜索/商品工具，不能凭模型记忆假定价格。

## 5. LLM 怎样访问数据库

LLM 不直接获得数据库账号，也不直接生成任意 SQL。推荐路径：

```text
用户问题
  → LLM 理解意图并选择只读/写入工具
  → 工具使用可信用户身份和结构化参数
  → FinanceService / 规划服务执行查询或事务
  → 返回结构化结果
  → LLM 解释结果
```

示例工具：

- `finance_get_month_snapshot(period)`
- `finance_list_recent_transactions(limit, category)`
- `finance_get_goal_progress(goal_id)`
- `finance_get_discretionary_allowance(horizon)`
- `finance_record_expense(...)`，必须走候选确认
- `market_get_position_performance(symbol)`，后续外部行情工具

这样能限制模型读取范围、保护隐私、保留审计、复用幂等和事务，并让图表与聊天使用同一份确定性结果。

### 5.1 Agent 记忆是否有帮助

类似 ChatGPT 或 Claude Code 的记忆文档对这个 Agent 有帮助，但不能把所有信息混在一个无限增长的 Markdown 中。应区分四类信息：

| 信息 | 正确来源 | 是否进入 Agent 记忆 |
| --- | --- | --- |
| 已发生交易、余额、预算事实 | 关系数据库和审计记录 | 否；每次通过工具查询 |
| 稳定偏好 | 可纠正的结构化记忆 | 是，例如喜欢冰红茶、偏好低成本活动 |
| 生活约束与目标 | 目标/计划数据库，必要摘要进入上下文 | 是，例如月底前必须预留交通费 |
| 对话原文 | 会话记录和保留策略 | 默认不自动变成长期记忆 |

记忆项至少要有：类型、内容、用户明确提供或系统推测、来源、确认状态、创建/更新时间、可选失效时间和敏感级别。系统推测不能静默当成事实；用户必须能在记忆中心确认、纠正或删除，并能说“记住这个”或“忘掉这个”。

运行时只检索与当前问题相关的少量记忆。例如“这 10 元怎么花”可以读取已确认的饮料偏好和当前目标，但不能把全部历史对话、所有账目或无关隐私都发送给模型。为了可读和备份，可以生成一份人类可编辑的 `memory.md` 导出文件；数据库中的结构化记忆仍是运行时事实来源。

### 5.2 可视化账本和 Agent 纠错

LLM 的解析可能出错，因此所有 Agent 产生的消费都要经过下面的可见状态：

```text
消息原始意图
  → 结构化待确认候选
  → 用户确认
  → 已入账事实
  → 发现错误时创建可审计纠错/冲正
```

桌面账本需要提供：

- 月/周消费趋势折线图、分类构成、预算进度和异常变化；
- 交易列表，按时间、金额、分类、账户和来源渠道筛选；
- 详情页显示 Agent 识别结果、用户确认、数据库回执和后续纠错历史；
- 待确认队列，允许修改候选后再提交；
- 已入账错误不能静默覆盖历史事实，使用项目冻结的纠错、撤销、冲正或重新分类命令，并保留审计。

P4 首版至少实现交易列表、筛选、详情和待确认状态。复杂纠错命令若当前后端缺失，需要单独冻结接口后由执行智能体实现，不能让前端直接改数据库。

## 6. 目标进度与主动汇报

“提前、正常、落后、超支”由规划程序按冻结规则计算。例如：

- 时间进度 50%，目标资金完成 65%：可能为提前；
- 时间进度 50%，目标资金完成 48%：可能为正常；
- 时间进度 80%，只完成 40%：可能为落后；
- 某预算分类净支出超过额度：超支。

阈值、宽限区间、收入延迟和临时必要支出需要以后单独设计。LLM负责把状态翻译成容易理解的汇报，并提出可选调整，不负责私自改预算。

主动提醒不能依赖 LLM 自己“醒来”。后台调度器定时取得最新快照、运行规则、生成提醒事件，再通过桌面通知或微信发送。迷你助手只展示提醒和接受点击。

## 7. 投资与股票模块边界

后续可以实现：

- 手工录入持仓、成本、数量和交易日期；
- 从有授权的行情服务取得带时间戳的现价和涨跌；
- 计算浮动盈亏、仓位集中度和目标资产配置偏差；
- 搜索公司公告、基金资料或宏观信息并保留来源；
- 结合用户知识进度解释概念、风险和情景。

用户提出“每天打开投资模块时更新一次”，首版可以采用**按打开刷新**：进入模块后调用行情工具取得最新可用报价和历史序列，显示行情时间、交易日和数据是否延迟，然后缓存本次结果；提供手动刷新，但不持续轮询。严格意义上的实时分时行情需要数据源授权、交易所时段、频率限制和可能的费用，后续按实际需要增加。

折线图的数值由行情工具返回的历史序列生成，例如近 7 日、30 日、1 年收盘价；持仓盈亏由程序根据数量、成本和报价计算。LLM只负责解释走势、事件和风险，不能修改价格或自己计算一个“看起来合理”的行情。

模型不能凭训练记忆回答实时涨跌。行情、汇率和计算必须来自工具。首版不连接券商、不自动交易；“推荐股票”应先拆成目标、期限、风险承受能力、应急资金、集中度和证据，再给出教育性比较与风险说明，最终操作由用户决定。

## 8. P4 推荐最小纵向切片

P4 不一次实现全部愿景。建议先交付一个能闭环使用和学习的桌面基础：

1. Electron + React + TypeScript Windows 桌面壳。
2. 首页财务驾驶舱，先显示虚拟/测试账户的月度快照、预算进度和近期交易。
3. 账本页面提供消费趋势、交易列表、筛选、详情、来源和待确认记录，让用户核对 Agent 结果。
4. 右侧可展开 AI 聊天面板，连接现有 P2 Agent API。
5. 聊天支持一条真实纵向链路：“午饭 18 元”→ 候选 → 用户确认 → 写入 → 首页和账本刷新。
6. 聊天支持只读提问：“本月花了多少”“最近五笔支出是什么”。
7. 一个迷你助手窗口或托盘入口，点击后打开同一聊天；P4 只实现入口和状态展示，不实现定时主动提醒。
8. 明确连接中、加载中、待确认、成功、可重试故障和后端离线状态。

P4 暂不包含：真实个人数据迁移、完整规划引擎、可自由支配公式、主动提醒调度、行情 API、股票推荐、券商交易、自动更新和正式安装包。它们分别进入后续纵向切片。
