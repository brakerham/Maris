# 阶段 0：前期任务分配

更新日期：2026-09-14。状态：D1、B1、C1 和 B1 对应 C2 已完成；B2 尚未开始。

## 阶段目标

阶段 0 只验证两条关键链路：

1. 用户输入 → 模型选择工具 → Python 执行确定性财务计算 → 模型解释结果。
2. 手机微信 → OpenClaw 微信通道 → 项目 Python 探针 → 微信返回可核对结果。

本阶段使用虚拟财务数据，不接入真实账单，不建设完整数据库，不实现正式桌面界面，也不租服务器。完成后再决定阶段 1 的数据模型与工程脚手架。

## 总体验收标准

- 最小 Agent 能在无真实密钥的测试模式下重复运行，并通过自动化测试。
- 配置 DeepSeek API 后，能观察一次完整工具调用；模型不得自行计算并伪装成工具结果。
- 未知工具、错误参数、超出最大循环次数和服务不可用都有明确失败结果。
- 微信探针的随机回执同时出现在 Python 日志与微信回复中；停止 Python 服务后不能回复“调用成功”。
- 2 分钟、1 小时和次日提醒分别记录“任务触发、平台接受、微信会话实收、手机通知”四层结果。
- 执行智能体提交自测证据，测试智能体独立复验；头脑风暴智能体核对证据后关闭阶段。
- D1、B1、B2、C1、C2 的执行过程按进度台账记录当前步骤与心跳；耗时本身不等于阻塞，超过下一检查点且无新输出时由总控诊断。

## 任务 A：头脑风暴与总协调

负责人：头脑风暴智能体（当前任务）。

工作范围：

- 维护本文件和总进度，处理需求变化与跨角色依赖。
- 在编码前汇总技术顾问的方案结论，确定阶段 0 的实现边界。
- 向执行智能体派发 B1/B2，向测试智能体派发 C1/C2。
- 微信实测前明确用户需要做的扫码和测试动作；不把安装完成当作链路通过。
- 核对最终交付与证据，决定进入阶段 1、补修或调整方案。

交付：任务状态、决策记录、风险与下一步。

## 任务 B：执行智能体

### B1：最小 Agent 核心

目标：用 Python 实现一个可阅读、可测试的小型工具调用循环。

建议范围：

- 虚拟财务快照和一个只读预算查询工具。
- Pydantic 工具参数模型、工具注册表、参数校验、执行结果封装。
- 可配置的模型适配层；提供不需要 API 密钥的确定性测试替身，并预留 DeepSeek 接入。
- 最大调用轮数、未知工具、重复工具调用、超时/供应商错误的处理。
- CLI 演示和结构化执行记录；日志不得包含密钥。
- pytest 自测及最小运行说明。

执行智能体可将“模型适配层”和“工具循环/财务工具”拆给不同执行子智能体，但必须先定义接口与文件边界，最终由执行智能体集成。

明确不做：正式预算算法、PostgreSQL、LangGraph、RAG、Electron 界面、多 Agent 业务架构。

### B2：微信桥接探针

依赖：B1 的 Python 服务接口草案；可与 B1 的内部实现并行准备。

目标：证明 OpenClaw 微信消息确实调用了本项目 Python 服务。

建议范围：

- Python 只读探针端点：每次生成随机回执、请求编号与时间，并记录脱敏日志。
- OpenClaw 自定义命令先做确定性桥接，再将同一能力注册为 Agent 工具。
- 服务停止、超时、坏响应和重复来源消息的明确处理。
- 实测步骤与结果记录写入 [微信验证步骤](wechat-validation.md)。

需要用户参与：实际安装/登录阶段在手机扫码；按约定发送测试命令和自然语言；确认微信会话与通知结果。

明确不做：读取微信历史、读取微信支付账单、正式主动提醒服务、群聊支持承诺。

执行交付：代码、实际文件索引、运行命令、自测结果、尚未验证项、给技术顾问的讲解入口。

## 任务 C：测试智能体

### C1：阶段 0 测试设计

可立即开始，不修改执行代码。

目标：依据本文件编写独立验收矩阵，至少覆盖：正常工具调用、错误参数、未知工具、多轮停止、模型/API 失败、工具异常、重复请求与日志脱敏。

微信部分至少覆盖：普通收发、随机探针一致性、Python 停服、重复消息、身份绑定、网关/服务重启，以及分层记录提醒结果。

交付：测试用例、所需观察点、准备条件与判定标准。测试不应照抄执行智能体的实现。

### C2：独立执行与结构审查

依赖：执行智能体交付可运行版本与版本标识。

目标：从干净环境运行相关检查，复现失败，审查模块边界、错误处理和可测试性。

发现问题先给出可复现报告。小型、可逆且已划定范围的测试或结构优化可以提交改动；行为变化与较大重构交回头脑风暴和技术顾问评估。修复后必须复测。

交付：通过/失败/未测清单、复现步骤、结构问题、实际测试输出摘要和剩余风险。

## 任务 D：技术顾问

### D1：实现前技术建议

目标：为阶段 0 给出短而具体的实现建议。

需要回答：

- DeepSeek 适配层与 Agent 核心怎样分界，怎样替换模型供应商而不污染业务工具。
- 工具 Schema 如何由 Pydantic 管理；测试替身如何证明调用循环而不是只测试固定回复。
- Python 探针适合采用 FastAPI 还是更轻量方式，以及这对阶段 1 的学习价值。
- OpenClaw 自定义命令和 Agent 工具各自验证什么；哪些部分属于 TypeScript 插件，哪些属于 Python 服务。
- 哪些日志足够支持调试和测试，同时保护个人数据与密钥。

交付：推荐方案、一个有意义的替代方案、选择理由、建议目录边界、用户需要理解的 3—5 个知识点。结论交回头脑风暴智能体后再冻结执行接口。

### D2：实现后教学

依赖：B1/B2 的真实代码与 C2 的测试结论。

目标：围绕一次真实执行记录讲清“消息、模型、工具请求、Python 函数、工具结果、最终回答”的数据流，并安排一个小修改练习。不得把代码完成视为用户已经掌握。

## 任务依赖与顺序

1. A 派发 D1、B1 和 C1；三者可并行。
2. D1 给出建议后，A 与 B1 确认接口和目录边界。
3. B1 完成自测；C2 独立验证 B1。
4. B2 在桥接接口稳定后接入微信；用户参与扫码和实收确认。
5. C2 验证 B2，并根据真实环境记录未覆盖能力。
6. D2 使用最终代码与测试证据教学；A 汇总并决定阶段 0 是否完成。
