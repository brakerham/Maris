## H1 失败的已知边界

H1 已消耗一次真实辅助启动。其独立 helper userData 与 W1 产品 profile 不同；ready 存在，release 不存在，native result/checks 未产生。源码中的产品 owner/outbox 读取和解密均在 release 之后。不能把 H1 记为 safeStorage 不可用，也没有依据说本次辅助初始化改写了产品 profile。

已定位的工具缺口：

1. runner 将 observer 的所有非零/未取得退出状态统一抛为 `ownership_observer_error`，没有保存 status、signal、error.code、耗时和 stderr 安全分类。
2. 全量 CIM、C# 类型准备、监听和窗口观察共用一次 8 秒同步调用，没有阶段落盘。约 8.59 秒的间隔接近这个时限，仍不足证明首次就是超时。
3. ready 文件只检查存在，没有核对其中 PID 与直接 spawn 的 PID 相同。
4. 监听枚举使用 SilentlyContinue，未区分查询失败与成功的空结果。

随后一次观察成功建立所有权并定向清理，证明此次失败收口有效，不能补填首次原因。辅助 exit 1/forced 与 W1 exit 0/natural 分开保留。`h1_readonly_review` 内部子任务独立只读复核了上述位置、profile 边界及预算算术，没有运行目标或修改文件。
