# 智能体进度台账使用规则

这个目录是项目共享的进度事实来源。它解决两个问题：总控智能体如何知道其他智能体做到了哪里，以及“完成”是否有证据。

## 目录结构

```text
docs/coordination/
├── README.md                 # 台账规则
├── overview.md               # 总控面板，仅头脑风暴智能体维护
└── agents/
    ├── brainstorm.md         # 头脑风暴/总协调日志
    ├── technical-adviser.md  # 技术顾问日志
    ├── executor.md           # 执行智能体及其子任务汇总
    └── tester.md             # 测试智能体日志
```

执行智能体创建的子智能体由执行智能体汇总到 `executor.md`；技术顾问创建的教学子任务由技术顾问汇总到 `technical-adviser.md`。子任务增多后再建立独立任务文件，避免一开始产生大量空文档。父智能体不能只写“子任务运行中”：每个活动子任务都要汇总当前步骤、最近心跳、下一检查点、等待对象和可观察的会话或输出路径，才能判断具体慢在哪里。

## 状态词汇

| 状态 | 含义 |
| --- | --- |
| `unverified` | 无法从当前任务直接核实是否已建立、接单或运行 |
| `ready` | 任务说明和依赖已经齐备，可以派发 |
| `assigned` | 已明确发送给对应智能体，但尚未收到开始记录 |
| `in_progress` | 对应智能体已经记录接单，并正在工作 |
| `blocked` | 有明确阻塞原因、已尝试的处理和解除条件 |
| `review` | 已交付，等待独立验证或总控验收 |
| `complete` | 交付物存在，所需验证已完成，总控已核对验收标准 |
| `cancelled` | 经总控或用户决定不再继续，并记录原因 |

“已经写了代码”和“自测通过”通常进入 `review`；只有满足任务定义的独立验证及总控验收后才进入 `complete`。

## 每个角色文件必须记录

- 当前连接状态：是否能直接确认该智能体已经接单。
- 当前任务、任务状态、开始/更新时间。
- 输入版本或所读文档。
- 负责和禁止修改的范围。
- 已完成工作及其文件链接。
- 实际运行的验证、结果与证据。
- 阻塞、需要谁处理、解除条件。
- 下一步和交接对象。
- 按时间倒序追加的工作日志。

## 运行可见性与慢任务诊断

任务状态描述“工作做到哪里”，运行状态描述“当前是否还在推进”。两者分开记录。例如，任务可以是 `in_progress`，运行状态可以是 `waiting_dependency`。

每个正在执行的角色文件顶部必须包含 `当前执行快照`：

| 字段 | 用途 |
| --- | --- |
| 当前步骤 | 正在读资料、编码、安装、运行哪组测试或等待哪项依赖 |
| 步骤开始时间 | 计算该步骤已经持续多久 |
| 最近有效进展 | 最近一次产生新代码、测试输出、决策或外部响应的时间 |
| 最近心跳 | 智能体最后一次确认仍在处理该任务的时间 |
| 下一检查点 | 下一个可核查输出和预计检查时间；不是无法证实的完成时间承诺 |
| 等待对象 | 依赖的智能体、用户、网络、外部 API、审批或运行进程 |
| 活动进程/会话 | 可安全记录的命令摘要、会话 ID、测试文件或日志路径；不记录密钥参数 |
| 重试与最后输出 | 重试次数、最近一条有诊断价值的脱敏输出 |

运行状态使用：

| 运行状态 | 含义 |
| --- | --- |
| `active` | 最近有有效进展，当前步骤仍在推进 |
| `waiting_dependency` | 等待另一个项目任务或接口 |
| `waiting_user` | 等待用户必须完成的扫码、选择或授权 |
| `waiting_external` | 等待网络、外部 API、安装、CI 或长进程 |
| `retrying` | 已发生失败，正在按记录的次数和原因重试 |
| `idle` | 已接单但当前没有运行步骤，必须说明原因 |
| `stale` | 超过下一检查时间仍无心跳；状态未知，需要总控检查 |
| `stalled_suspected` | 连续错过两个检查点，且没有新输出或明确等待对象；疑似停滞 |
| `finished` | 当前角色在该任务上的执行已经结束，等待或完成验收 |

预计超过五分钟的操作，执行前先写入当前步骤和下一检查点。智能体能够取得执行控制时，在出现有效输出或至少每十分钟更新一次心跳；若工具调用期间无法写文件，必须提前注明，并在控制返回后立即更新。

父智能体同时运行多个子任务时，还必须维护下面的子任务快照；子任务结束后保留最终行及交付链接，不能用新的任务覆盖旧记录：

| 子任务 | 任务状态 | 运行状态 | 当前步骤 | 最近心跳 | 下一检查点 | 等待对象 | 会话/证据 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `<task-id>` | `in_progress` | `active` | `<具体操作>` | `<时间>` | `<输出与时间>` | `无` | `<安全的会话或路径>` |

父智能体从子智能体收到阶段消息、工具输出或结束通知后立即刷新这一行。如果父智能体无法读取子智能体的运行过程，要明确写“仅能看到最后一次消息”，不能填入推测的当前步骤。

总控发现超时后按以下顺序检查：角色日志 → 子任务快照 → 活动命令/会话输出 → 依赖状态 → 最近错误与重试。`stale` 只表示可见性过期，不等于失败；没有证据时不能擅自终止或重复启动可能造成写入的操作。

进度百分比只有在存在可数单位时使用，例如“20 个测试完成 12 个”。其余情况记录已完成步骤、当前步骤和剩余步骤。

## 更新责任

- 各智能体只维护自己的角色文件，避免互相覆盖状态。
- 头脑风暴智能体读取各角色文件、核对仓库事实，并更新 `overview.md`。
- 头脑风暴智能体不能仅根据角色文件中的一句“完成”关闭任务；还要检查交付路径和必要验证。
- 无法直接看到另一个 Codex 任务是否在线时，以共享文件中的最近更新时间和证据为准，并明确写成“未核实在线状态”。
- 用户作出的范围或优先级决定由头脑风暴智能体同步到总览和项目计划。

## 完成记录模板

```markdown
### YYYY-MM-DD HH:mm Asia/Shanghai — <task id>

- 状态：review | complete | blocked
- 完成内容：
- 交付物：
- 验证命令与结果：
- 未验证内容：
- 阻塞或风险：
- 下一步/交接：
```

## 当前执行快照模板

```markdown
## 当前执行快照

- 运行状态：active | waiting_dependency | waiting_user | waiting_external | retrying | idle | stale | stalled_suspected | finished
- 当前步骤：
- 步骤开始时间：YYYY-MM-DD HH:mm Asia/Shanghai
- 最近有效进展：YYYY-MM-DD HH:mm Asia/Shanghai
- 最近心跳：YYYY-MM-DD HH:mm Asia/Shanghai
- 下一检查点：<可核查输出>；YYYY-MM-DD HH:mm Asia/Shanghai
- 等待对象：无 | <角色/用户/外部服务/进程>
- 活动进程或会话：无 | <脱敏命令摘要/会话 ID/日志路径>
- 重试次数：0
- 最近输出：
```

日志里不记录密钥、个人账单、微信账号标识或未脱敏的模型输入输出。
