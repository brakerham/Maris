## 问题与技术选择

已知基线是 23 项执行方 Agent 测试中 18 通过、5 项触发 `pending_action_expired`。夹具把 `RECEIVED_AT` 固定为 2026-09-16 12:00 UTC，但 `AgentApplication.get` 会调用没有显式 `now` 的 `PendingActionStore.get`。`resume(now=...)` 内部也经过这条查询，所以只向外层传时间仍不足以隔离系统日期。

本次限定为测试基础设施维护，技术选择如下：

| 方案 | 取舍 |
| --- | --- |
| pytest 函数级 fixture + monkeypatch 替换被测模块引用的 datetime | 本次采用；可推进模拟时间、无需依赖，测试结束自动恢复 |
| 把固定日期改成今天或直接 datetime.now | 不采用；只是移动日期依赖，还会影响固定月份和余额断言 |
| 在生产构造函数中注入 Clock | 可作为后续架构议题；本次没有产品改动授权 |
| 引入全局冻结时间第三方库 | 本次没有必要新增依赖 |

实现前在自己的日志简要说明问题、选择、相关模块及数据流；在交接文档用实际代码说明 fixture、monkeypatch、TTL 和 HTTP 默认取时之间的关系，供技术顾问后续教学使用。
