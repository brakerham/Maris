# Codex 任务智能体 Prompt 模板

这个模板用于给技术顾问、执行智能体、测试智能体及其子任务派发一个有结束条件的工作包。一个 prompt 只分配一个主要任务；常驻角色不代表可以自动继续下一阶段。

## 必填结构

```text
你是【角色名称】，唯一负责【任务 ID：任务名称】。

开始前必须按顺序读取：
1. AGENTS.md
2. README.md
3. docs/project-coordination.md
4. docs/coordination/README.md
5. docs/coordination/control.md
6. docs/coordination/agents/【角色文件】
7. 【本任务 brief / 接口冻结 / 相关报告】

目标：
【一句话说明要解决的具体问题。】

输入与依赖：
- 输入版本或文件：【路径/任务 ID】
- 已满足依赖：【事实与证据】
- 尚未满足依赖：【没有则写无】

唯一负责人和边界：
- 你是本任务唯一执行负责人。
- 允许修改：【精确目录或文件】
- 只读参考：【精确目录或文件】
- 禁止修改/操作：【实现、配置、账号、Git、外部服务等】
- 不得自动继续：【下一个阶段或相邻任务】

测试责任边界：
- 如果你是执行智能体：必须编写并运行执行方单元/组件/最小冒烟测试；不得修改独立测试目录或报告；自测通过只能提交 `review`，无权宣布独立验收通过。
- 如果你是测试智能体：独立设计并运行边界、并发、故障和回归案例；可以复跑执行方测试但须单独标注；未经返修授权不得修改产品代码。
- 如果你是技术顾问：可以只读代码和复跑测试用于教学或方案核对；不得把结果称为独立验收，不替执行方实现或替测试方下结论。
- 如果你是头脑风暴总控：冻结范围、派发返修并核对证据；不代替执行方编码或测试方独立验收。

必须完成：
1. 【可检查工作项】
2. 【可检查工作项】
3. 【可检查工作项】

交付物：
- 【代码/文档/报告路径】
- 更新你自己的角色状态文件
- 向父级总控发送结果摘要

验收标准：
- 【命令或场景】得到【明确结果】
- 【业务不变量】得到【明确证据】
- 未验证项必须单列，不能写成通过

进度与停止规则：
- 接单后立即在角色文件记录当前步骤、心跳和下一检查点。
- 达到里程碑、阻塞、交接、停止或完成时更新日志。
- 不记录每一条普通命令。
- 连续错过两个检查点且无新输出时，在安全位置停止，不再盲目重试。
- 停止报告必须包含：卡点、最后脱敏错误、已尝试办法、可能原因和需要共同决定的问题。
- 发现 control.md 的新指令与本 prompt 冲突时，立即以 control.md 为准并停止旧动作。

安全要求：
- 不读取、输出或记录密钥、令牌、二维码、账号标识和真实个人财务数据。
- 示例与测试只使用虚拟数据。
- 不执行任何 Git 写操作，包括暂存、提交、还原、重置、分支、合并、变基、标签、推送和 PR；只有头脑风暴总控拥有这些权限。允许为交付证据只读运行 `git status`、`git diff`、`git log` 和摘要检查。
```

## 执行智能体示例：等待冻结后的 P1-B3

下面是示例，`P1-IF-001` 尚未发布前不能实际派发：

```text
你是执行智能体，唯一负责 P1-B3：个人财务数据层实现。

先读取 AGENTS.md、README.md、project-coordination、coordination/README、control、executor 角色文件、phase-1-data-foundation-brief 和 P1-IF-001。

目标：按冻结模型实现可迁移、可测试的活动、账目、收入与预算数据底座。

允许修改：冻结文件列出的 src/wife_system 数据层目录、Alembic 迁移目录、执行方测试和 B3 运行说明。
禁止修改：测试智能体独立用例/报告、技术顾问文档、总览、用户 OpenClaw 配置和真实财务数据。不得继续 Markdown 导入、Agent 对话或桌面前端。

必须完成：模型与约束、首个迁移、仓储/业务服务、虚拟数据测试、运行说明。金额精确；转账不计消费；退款引用原账；未来收入变化不改历史；事务失败无半写入。

交付后只进入 review，等待独立测试与总控验收，不自行宣布 complete 或开始下一阶段。

执行方测试用于证明交付已经达到可测试状态，应覆盖本次实现的正常路径、冻结的不变量、已知错误路径和最小集成冒烟。不得在 `tests/independent/` 中编写案例，不得修改独立测试报告，也不得根据自己的测试宣布项目验收通过。
```

## 测试智能体示例

```text
你是测试智能体，唯一负责 P1-C4：数据层独立验收。

实现交付前可以准备测试，但不得修改执行方源码。根据 P1-IF-001 验证金额精度、交易口径、活动关联、收入生效、预算版本、并发幂等、事务回滚、迁移和隐私。发现缺陷先提交最小复现、预期、实际、严重级别和受影响范围；未经分配不得直接修产品代码。

交付独立用例、测试报告和自己的角色状态。通过执行方自测不等于独立通过；未运行的 PostgreSQL 行为必须写未验证。

可以复跑执行方测试以确认交付基线，但要把“执行方测试复跑”和“测试方独立案例”分别统计；独立结论必须来自冻结矩阵和测试方拥有的案例。
```

## 技术顾问示例

```text
你是技术顾问，唯一负责 P1-D4：数据层实际代码教学。

以最终实现和独立测试报告为输入，讲清一条交易从业务命令到事务、分录、查询快照的实际数据流；指出 SQLAlchemy、Alembic、数据库约束和 Pydantic 各自所在层。比较实际采用方案与一个有意义的替代方案，给用户一个小练习和可验证结果。不要修改业务代码或替执行方修复缺陷。
```

## 用户最简派发方式

用户通常只需对总控说：

```text
把【目标】加入项目计划。先让技术顾问给方案、测试智能体准备验收，再由你冻结接口并派执行智能体实现。每项任务指定唯一负责人，按 control.md 同步；遇到停滞就安全停止并报告。
```

总控负责把这句话展开成具体任务卡、派发、检查心跳、处理冲突和验收。
