# 微信接入验证步骤

状态：验证计划。尚未安装插件、配置账号、实现桥接、发送测试消息或安排提醒。下文中的测试用语需对应联调工具实现后才有意义。

## 验证目的与分工

先确认微信收发，再确认本项目 Python 后端参与执行，最后验证无人继续聊天时的定时提醒。最小实验使用虚拟数据，无需提前建设完整财务系统或桌面界面。

开发方负责检查运行环境与版本、准备插件和服务、实现受约束的联调工具、配置路由、采集脱敏日志、分析失败原因。外部账号授权与需要的安装许可在具体操作时处理。

用户负责手机微信扫码授权、发送给定测试文字，以及确认会话里是否出现预期消息和手机是否弹出通知。无需自行研究接口、编写桥接代码或分析服务端日志。

## 步骤一：准备本地运行环境

开发方确认当前 OpenClaw 与腾讯插件兼容版本、运行位置、账号状态和来源身份限制。文档记录的插件配对问题需按实际安装版本复核。

先在能运行所需服务的电脑上做实验，保持联网、服务进程运行且电脑不休眠。Python 后端、OpenClaw 网关与提醒任务可能是不同进程，关闭桌面窗口不代表它们仍在后台运行，需要分别检查。

初次无需为该验证先租服务器。后续若要求电脑关机时仍能聊天和提醒，再选择持续运行的服务部署位置。

## 步骤二：扫码与普通收发

1. 开发方准备登录入口；用户使用手机微信扫描当次二维码并在手机确认授权。已有可用通道则检查状态，不重复设置。
2. 用户向机器人发送：“联调收发测试 V001”。
3. 开发方核对入站消息、账号与发送者绑定，以及出站消息记录。
4. 用户确认微信会话收到对应回复。

通过条件：能将同一次请求与回复关联起来。此步骤仅证明通道可收发，还没有证明自建 Agent 接通。

## 步骤三：证明请求到达自建后端

开发方先实现一个只读自定义命令，将请求确定地转交本地 Python 服务。OpenClaw 官方提供 `api.registerCommand`（绕过 LLM 的命令）与 `api.registerTool`（供 Agent 调用的工具）；先验证命令，再验证模型选择工具，便于分别定位网络桥接与模型行为问题。[官方工具与命令接口](https://docs.openclaw.ai/plugins/sdk-overview/tools-and-commands)

用户首先发送准备好的测试命令，例如 `/finance-probe V001`。这是拟实现的项目命令，当前尚不可用；实际命令名称与渠道解析行为在接入时确认。

Python 后端为该次调用生成新的随机标记、请求编号和时间，记录结果并返回给微信，例如 `POC-V001-<后端生成的随机值>`。标记不得提前放入模型提示词或用固定回复替代。

通过条件：后端执行日志、命令返回和手机实际回复中的请求编号与标记一致。验证中另一次调用应得到新的标记。

开发方短暂停止 Python 服务后再发一次测试请求，系统应报告服务不可用或明确失败，不能继续编造“调用成功”。恢复服务后重新验证。

命令验证通过后，开发方将同一操作暴露为工具，用户再发送：“调用项目联调工具，生成本次验证标记。”检查模型是否选择正确工具及工具返回是否与后端匹配。随后最小财务 Agent 接入时，还需观察本项目的模型调用和预算工具执行记录；一次固定回声不等于完整 Agent 验证通过。不能假设修改一个通道 URL 就能接入任意 Python Agent。

## 步骤四：定时提醒

开发方准备真正的调度任务与发送工具；模型口头回答“会提醒”不算创建任务。每个任务保存计划时间、目标账号、内容标记、执行状态和投递结果。

在同一次初始安排中设定几次测试，例如 2 分钟后、1 小时后和次日同一时间。后两个区间是测试样本，不代表平台规定的有效期。期间用户不向机器人发新消息；若发生了新交互，就记录实际最后交互时间，重新安排需要的静默区间。

用户可按准备好的联调指令发送：“创建联调提醒：2 分钟后、1 小时后、明天同一时间分别发送测试标记。”开发方检查后台确实生成了对应任务，而不是只收到自然语言承诺。

用户需要：保持接收账号可用，按约定保持承载服务的电脑运行，观察短时提醒，并在之后自然检查长时提醒；无需坐在电脑前连续等待。可以锁屏，分别记录是否弹通知及打开微信后是否能看到消息。

开发方核对四项证据：调度任务是否触发、通道是否接受发送、用户是否实际看到消息、手机是否弹出通知。接口返回成功不能单独作为送达证据。

通过条件：记录清楚已成功的实际静默区间与测试环境。某次次日提醒成功不证明无限时长的主动消息都能成功。

## 步骤五：恢复与重复处理

开发方在测试任务到期前重启服务，检查任务是否保留并按约定执行。另行模拟重复投递，确认同一来源消息不会重复记账、同一提醒不会无控制地重复发送。

用户两次主动输入相同金额可能代表两笔真实消费；去重验证应重放同一来源消息标识，不能简单按文字相同就丢弃。

需要发送者权限检查时，由开发方使用隔离测试数据检查未绑定身份被拒绝，不要求用户提供额外账号或向其他人发送测试消息。

## 失败时怎样定位

| 现象 | 开发方优先检查 |
| --- | --- |
| 普通消息没有进入网关 | 登录、网络、版本、账号与发送者限制 |
| 网关收到消息，Python 没有记录 | 桥接配置、工具选择、鉴权和地址可达性 |
| 后端有结果，微信没有回复 | 出站通道、上下文、平台错误与格式 |
| 到点没有发起发送 | 调度状态、进程存活、休眠、时区和重启恢复 |
| 平台接受但会话没消息 | 平台投递结果与用户实收情况，保持“未确认送达” |
| 会话有消息但手机没通知 | 微信及系统通知设置、免打扰、其他设备登录状态 |
