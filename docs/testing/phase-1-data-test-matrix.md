## 1. 判定原则与证据层

本矩阵先于 P1-B3 实现形成，独立从财务正确性、事务一致性和数据库风险设计。它不把某种 ORM、金额表示或交易模型当作既定事实。依赖技术选择的断言必须在总控发布 `P1-IF-001` 后绑定到冻结接口；没有运行的案例一律标为“设计完成/未执行”，不能写成通过。

观察层统一使用以下名称：

| 层 | 必须观察的证据 |
| --- | --- |
| 输入/接口 | 请求模型、字段规范化结果、稳定错误码；不能只看自然语言说明 |
| 业务服务 | 返回对象、业务不变量、调用次数、版本和聚合结果 |
| 持久化/约束 | 实际行、唯一/外键/检查约束、受影响行数、数据库异常分类 |
| 事务/并发 | 提交与回滚边界、锁/版本冲突、两个独立连接的最终可见状态 |
| 迁移 | 空库与已有库的 schema 版本、升级/回退输出、数据前后校验和 |
| 日志/审计 | 脱敏事件、关联 ID、修订原因；不得含完整描述、来源载荷、账户标识或堆栈 |

“通过证据”至少包含：实现快照或提交号、数据库及版本、迁移版本、测试命令和退出码、断言结果，以及必要的脱敏数据库查询摘要。只在 SQLite 通过不能替代标记为 PostgreSQL 必测的案例。

### SQLite 与 PostgreSQL 的必测差异

| 风险面 | SQLite 必看 | PostgreSQL 必看 | 关联案例 |
| --- | --- | --- | --- |
| 数值 | 动态类型/affinity 是否允许错误存储类别；应用转换是否精确 | `NUMERIC`/整数边界、scale 和驱动 Decimal 往返 | AMT-01～08、MIG-07 |
| 外键 | 每条应用连接是否真正启用外键 | 外键及延迟检查行为是否符合冻结事务边界 | ERR-02、MIG-06 |
| DDL 迁移 | 表重建、约束变更和失败恢复可能非事务化 | 事务 DDL 失败是否整体回滚 | MIG-03～05 |
| 并发 | 单写者/锁错误的稳定映射，不能把串行测试当并发证明 | 独立连接下唯一竞争、行锁/版本冲突和隔离级别 | TRF-06、REF-06、BUD-07、IDM-03～04、MIG-09 |
| 时间 | 无原生时区类型时的序列化和查询一致性 | timestamptz/等价类型的连接时区与月界查询 | LED-07、MIG-08、SNP-08 |
| 约束 | CHECK、严格表或替代防线的真实执行效果 | 完整数据库约束与异常类型映射 | ERR-01～04、MIG-05 |

## 18. P1-C4 独立验收进入与完成条件

### C4 进入条件

1. B3 提供不可变提交号或完整文件 SHA-256、Python/依赖锁、数据库版本及迁移 head。
2. `P1-IF-001` 已冻结且能把 F01～F15 映射到实际接口、表关系或明确范围外项。
3. 从空库安装、已有库升级、开发回退/重建和 PostgreSQL 测试环境均有可执行命令；不要求测试智能体修改实现来启动测试。
4. 执行方自测和运行说明已交付；已知失败、限制及数据库差异如实记录。
5. 只提供虚拟夹具；若发现真实个人数据、凭据或未脱敏日志，C4 停止采集并报告。

### C4 完成条件

1. 所有 P0 案例在其适用数据库执行；PostgreSQL 必测案例不能用 SQLite 结果替代。
2. 每个案例记录状态、实现快照、数据库/迁移版本、命令、实际结果和证据位置；未测必须有原因。
3. 金额精度、转账/退款原子性、历史不变、幂等并发、迁移数据保持、月度快照和隐私均无未分级失败。
4. 失败修复后重跑原案例、相邻业务不变量和迁移/快照回归。
5. 测试智能体提交独立报告；总控核对交付与未验证项后，才能把 B3 标为 `complete`。

## 20. 尚未解决的业务口径

这些项目必须由总控结合 D3 建议在 `P1-IF-001` 中作出明确决定；C3 只保留风险，不代替产品决策：
