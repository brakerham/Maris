# 阶段 0 独立验收矩阵（C1）

更新日期：2026-09-13。状态：`review`（测试设计完成，尚未执行）。

## 1. 范围与判定原则

本矩阵独立依据阶段 0 目标和业务风险设计，不以执行智能体的测试实现作为通过依据。当前没有冻结的接口版本或可验收版本，因此所有案例均为 `未执行`；实际执行属于 C2。

阶段 0 验证两条链路：

1. 用户输入 → 模型提出工具调用 → Python 校验并执行虚拟财务工具 → 模型基于真实工具结果回答。
2. 微信消息 → OpenClaw → Python 探针 → 可核对回执返回微信，以及失败、重复、身份和提醒状态的可观察性。

统一判定规则：

- `通过`：实际结果满足本用例全部判定标准，并保存可复现证据。
- `失败`：实际行为与任一判定标准冲突，记录输入、预期、实际、环境/版本和证据。
- `未测`：依赖、账号、环境或接口尚未具备；必须写明原因，不能视为通过。
- 自动化测试通过只能证明其覆盖的行为；真实 DeepSeek、OpenClaw、微信会话和手机通知须分别取证。
- 机器可判定的稳定错误码优先于自然语言文案；不得用“看起来合理”的模型回答代替工具执行证据。

## 3. Agent 核心与工具循环

| ID | 优先级 | 场景与输入 | 必看观察点 | 通过标准 |
| --- | --- | --- | --- | --- |
| A-01 | P0 | 确定性模型第一轮请求 `get_budget_snapshot`，第二轮给出最终文本 | 两次模型调用、一次工具执行、同一 `tool_call_id`、终态 | 工具恰好执行一次；第二轮模型历史包含对应结构化工具结果；最终文本与工具结果一致 |
| A-02 | P0 | 分别使用两份 `remaining_fen` 不同的虚拟快照运行相同输入 | 工具结果、最终文本、调用次数 | 两次工具结果和回答随快照变化，证明不是固定回复或模型自行编造 |
| A-03 | P0 | 模型首轮直接返回最终文本且不请求工具 | 工具调用计数、轮次、终态 | 不执行工具；一次模型调用后正常结束；记录“无工具调用” |
| A-04 | P0 | `arguments_json` 为截断 JSON 或非 JSON | 工具调用计数、错误码、终态 | 本地校验拒绝；工具不执行；返回稳定参数错误，原始坏参数不泄露到用户响应或非调试日志 |
| A-05 | P0 | 缺少必填字段 | Pydantic/等价本地校验结果、工具调用计数 | 工具不执行；错误能定位为参数校验失败，而非模型或工具异常 |
| A-06 | P0 | 字段类型错误，例如数组代替周期字符串 | 同上 | 工具不执行并返回稳定参数错误；不做含糊的隐式类型转换 |
| A-07 | P0 | 带未声明额外字段 | Schema 与运行时校验、工具调用计数 | 额外字段被拒绝；工具不执行 |
| A-08 | P1 | 字段语法正确但值超出允许范围 | 业务/枚举校验、错误分类 | 工具不执行；返回可区分的参数校验失败 |
| A-09 | P0 | 模型请求未注册工具名 | 注册表查询、工具调用计数、错误码 | 未执行任何处理函数；返回 `unknown_tool` 或冻结后的等价稳定码 |
| A-10 | P0 | 模型在同一运行内重复同一 `tool_call_id` | 每轮调用 ID、处理函数计数、终态 | 第二次重复被识别；不会再次执行工具；返回重复调用错误 |
| A-11 | P0 | 模型持续请求有效工具直到达到 `max_rounds` | 实际模型调用次数、工具执行次数、终态 | 不发生第 `max_rounds + 1` 次模型调用；返回最大轮次错误，不伪造最终回答 |
| A-12 | P1 | 工具调用后模型既不给最终文本也不给后续工具调用 | `finish_reason`、响应内容、终态 | 返回明确模型协议错误；不把空文本视为成功 |
| A-13 | P1 | 一轮包含两个合法工具调用（若冻结契约支持） | 执行顺序、各调用 ID、各结果对应关系 | 每个结果绑定正确 ID，不串结果；若阶段 0 明确不支持，应稳定拒绝而非部分静默执行 |
| A-14 | P0 | 工具处理函数抛出预期业务异常 | 异常分类、运行终态、后续模型调用 | 返回稳定 `tool_*` 错误；不伪造成正常工具结果；不泄露堆栈给用户 |
| A-15 | P0 | 工具处理函数抛出未预期异常 | 运行终态、日志关联、外部响应 | 外部仅得到通用错误和关联 ID；内部保留脱敏诊断；进程可继续处理下一请求 |
| A-16 | P0 | 工具执行超时或取消 | 取消是否生效、耗时、错误码、残留任务 | 在冻结超时界限内失败；不产生迟到的成功结果；下一请求不受污染 |
| A-17 | P1 | 工具返回无法序列化或不符合输出模型的值 | 结果校验、模型是否收到该值 | 结果在进入模型历史前被拒绝；返回工具协议错误 |
| A-18 | P1 | 连续执行两个独立 run，第二个使用不同脚本和快照 | 消息历史、调用计数、run ID | 两个 run 状态隔离；第二个运行不继承第一个的消息、结果或调用 ID |

## 4. 模型适配器与接口故障

| ID | 优先级 | 场景与输入 | 必看观察点 | 通过标准 |
| --- | --- | --- | --- | --- |
| M-01 | P0 | 模型调用超时 | 适配器调用次数、耗时、错误码、`retryable` | 返回 `model_timeout` 或冻结后的等价码；阶段 0 无隐藏重试；不执行工具 |
| M-02 | P0 | 上游认证失败 | HTTP/SDK 错误映射、日志 | 映射为认证错误且不可重试；响应和日志不包含 API key/Authorization |
| M-03 | P1 | 上游余额不足 | 错误映射、`retryable` | 与认证、限流、服务不可用可区分；不执行工具 |
| M-04 | P0 | 上游限流 | 调用次数、错误码、`retryable` | 映射为限流；阶段 0 不暗中重试；明确是否建议稍后重试 |
| M-05 | P0 | 上游 500/503 或连接失败 | 错误映射、运行终态 | 映射为服务不可用；不生成正常回答；后续独立请求仍可运行 |
| M-06 | P1 | 上游返回坏 JSON、缺失工具调用 ID 或不兼容响应 | 供应商原始响应到中立类型的转换边界 | 返回模型协议错误；原始响应不直接进入业务工具或用户答复 |
| M-07 | P0 | 未配置密钥时运行普通自动化测试 | 网络访问、测试选择、退出码 | 普通测试使用替身且不访问真实 API；测试可重复通过 |
| M-08 | P1 | 显式 live test 但缺少密钥 | 跳过原因、退出状态 | 清楚跳过或在启动前明确失败；不能误报真实 DeepSeek 已验证 |
| H-01 | P0 | 健康检查（接口冻结后） | 是否调用模型/工具、响应 | 仅证明 Python 进程可响应；不产生模型或工具事件 |
| H-02 | P0 | Agent HTTP 请求字段缺失、类型错误或额外敏感配置字段 | HTTP 状态、机器错误码、执行计数 | 请求在边界被拒绝；客户端不能指定供应商、密钥或任意工具；Agent 不启动 |
| H-03 | P0 | 同一幂等键、相同载荷顺序重放两次 | run ID、工具调用次数、`replayed`、响应 | 返回第一次结果/同一关联 ID；工具及模型副作用不重复；重放状态可见 |
| H-04 | P0 | 同一幂等键、不同载荷 | HTTP 状态、机器错误码、调用计数 | 返回冲突；不复用旧结果也不执行新 run |
| H-05 | P1 | 相同幂等请求并发到达 | 两个响应、底层调用次数、锁/存储行为 | 最多创建一个 run；另一个得到同一结果或明确的进行中状态，不重复执行 |
| H-06 | P1 | 客户端在结果产生前断开后重试 | run 状态、重试响应、执行计数 | 可通过幂等键查询/重放确定结果；不会因断线重复执行 |
| H-07 | P0 | Agent 映射模型超时、上游失败、本地未处理异常 | HTTP 状态、稳定 `error.code`、关联 ID | 每类故障按冻结契约区分；响应不含堆栈或供应商原文敏感内容 |
| H-08 | P1 | 服务处理一个失败请求后再处理正常请求 | 进程状态、第二次响应 | 失败不会破坏服务；第二次请求可得到正常且独立的结果 |

### 提醒结果分层矩阵

分别为 2 分钟、1 小时和次日同一时间建立独立记录；后两项是实际测试区间，不推导平台保证的最长有效期。静默期间若用户重新交互，记录真实最后入站时间并重新安排该样本。

| ID | 场景 | 任务触发 | 平台接受 | 微信会话实收 | 手机通知 | 判定标准 |
| --- | --- | --- | --- | --- | --- | --- |
| R-01 | 2 分钟提醒 | 待测 | 待测 | 待测 | 待测 | 四层分别记录；任一层未知均不得宣称端到端送达 |
| R-02 | 1 小时静默提醒 | 待测 | 待测 | 待测 | 待测 | 记录最后入站、计划/实际时间、环境与延迟 |
| R-03 | 次日静默提醒 | 待测 | 待测 | 待测 | 待测 | 只证明本次实际静默区间，不外推无限时长 |
| R-04 | 到期前重启提醒服务 | 待测 | 待测 | 待测 | 待测 | 任务持久保留并至多发送一次，或明确记录当前阶段不支持 |
| R-05 | 重放同一提醒投递事件 | 待测 | 待测 | 待测 | 待测 | 同一通知去重键不会导致无控制重复发送 |
| R-06 | 取消提醒后到期 | 待测 | 待测 | 待测 | 待测 | 不发起平台发送；取消状态和原因可核对 |

提醒整体结论必须使用精确措辞：

- “任务已触发”不等于平台接受。
- “平台接受”不等于微信会话实收。
- “微信会话实收”不等于手机弹出通知。
- 手机未通知但会话有消息时，记录微信/系统通知设置和其他设备登录状态，不误判为服务端未发送。

## 8. 待总协调冻结的验收参数

下列事项会影响 C2 的精确断言，但不影响本矩阵的风险覆盖：

1. `max_rounds` 是“最多模型调用次数”还是“最多工具执行轮次”，以及边界值 0/1 是否允许。
2. Agent HTTP 端点的请求/响应字段、幂等键位置、错误状态码和稳定机器错误码。
3. 同一模型轮次多个工具调用是全部支持、顺序执行、并发执行，还是阶段 0 明确拒绝。
4. Agent run 的重复请求保证是否需要跨进程重启；探针去重是否仅在进程生命周期内。
5. 工具超时边界、模型超时边界，以及取消后迟到结果的处理。
6. B2 固定使用的 OpenClaw、腾讯微信插件版本和身份绑定策略。
7. 阶段 0 是否真正实现提醒调度；若不实现，R-01～R-06 保持 `未测`，不得影响对 B1 核心的局部结论，也不得宣称阶段 0 整体完成。

## 9. C2 交付格式

C2 按本矩阵逐项记录：案例 ID、状态（通过/失败/未测）、代码版本、环境、运行方式、实际输出摘要和证据位置。缺陷报告包含最小复现输入、预期、实际、影响和关联日志 ID。任何修复完成后重跑原失败案例及相邻回归案例。
