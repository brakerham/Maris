## 5. SQLite 证据

SQLite 使用每个案例独立的临时文件数据库。已验证：

- 空库从 base 升到 head、重复 upgrade、唯一迁移版本号、17 张业务表、代表性 CHECK/UNIQUE/FK/索引。
- 带虚拟收入数据重复 upgrade 后主键、金额、引用和余额保持。
- 开发/测试降到 base 后重建 head；降级会清空业务数据，未把它描述为生产回滚。
- 受控迁移失败不会删除未知既有表和虚拟标记；全新数据库可重新升级恢复。
- `make_engine` 创建的每条 SQLite 应用连接均启用外键，孤儿审计写入被拒绝。
- 收入、支出、负余额、期初余额、转账、退款、冲销、活动、收入预计、预算、幂等、事务回滚和月度快照主路径。
- SQLite 两连接同键/冲突键、并发转账、并发退款和并发预算发布；成功写入完整，锁错误只接受安全错误码，未观察到半写入或余额漂移。
- Asia/Shanghai 月界和跨月退款统计正确；首轮公开读取时间失去时区信息，R2 已复验修复，见第 10 节。

SQLite 与 PostgreSQL 的差异没有被抹平：SQLite 依赖服务层平衡校验，没有 PostgreSQL 延迟平衡触发器；SQLite 为动态类型且 DDL 非事务化；SQLite 并发是单写者/锁模型。SQLite 结果不替代 PostgreSQL 验收。

## 7. 首轮可复现缺陷

以下条目保留首轮复现证据。R2 状态均为“已修复并独立复验通过”，当前结论见第 10 节。

### C4-DATA-001：多次小额退款累计分摊破坏原分类比例

- R2 状态：已修复并独立复验通过。

- 关联：AMT-05、REF-03、F02、F06
- 级别：高，财务分类正确性
- 前置：一笔拆分支出，两类各 1 分。
- 操作：顺序提交两次各 1 分退款。
- 预期：累计全额退款后，两类各退款 1 分，任何分类净支出均不为负。
- 实际：稳定余分每次都落到同一原分录，最终一类退款 2 分、净支出 -1 分，另一类退款 0 分。
- 边界：交易总额仍守恒，问题在多次退款的累计分类分配。

### C4-DATA-002：SQLite 接受非整数金额存储类别

- R2 状态：已修复并独立复验通过。

- 关联：ERR-01、MIG-07、F01
- 级别：高，数据库完整性
- 前置：迁移后的 SQLite head，存在合法预算版本和第二个支出分类。
- 操作：绕过服务层，向 `budget_allocation.limit_minor` 写入文本型虚拟 canary。
- 预期：数据库约束拒绝非整数存储类别，不产生非法金额行。
- 实际：SQLite 接受该文本值，现有 `BIGINT` affinity 和 `limit_minor >= 0` CHECK 未阻止动态类型污染。
- 边界：公开命令服务的字符串解析仍会拒绝非法金额；缺陷位于 SQLite 持久化防线。

### C4-DATA-003：SQLite 公开交易时间返回 naive datetime

- R2 状态：已修复并独立复验通过。

- 关联：MIG-08、F14
- 级别：中，双库一致性和调用方解释风险
- 前置：以 `2026-09-01T00:30:00+08:00` 写入虚拟收入。
- 操作：通过公开 `list_transactions()` 读取。
- 预期：返回 aware UTC `2026-08-31T16:30:00+00:00`。
- 实际：值为 UTC 墙钟时间 `2026-08-31 16:30:00`，但 `tzinfo` 为 `None`。
- 边界：当前月界查询案例通过；风险在公开返回值和 SQLite/PostgreSQL 往返语义不一致。

## 8. 错误、隐私与结构检查

- Pydantic 严格拒绝 float、int、Decimal 进入金额字符串字段；NaN、Infinity、科学计数、负数、零和越界值按冻结错误分类处理。
- 同键同载荷返回原结果并标记 replay；同键冲突载荷返回 `duplicate_request_conflict`；失败事务不留下成功收据。
- HMAC 摘要长度和唯一范围符合冻结接口；原始 `source_event_id` 未出现在收据、结果或审计行。
- 成功、业务校验、唯一/检查约束、数据库不可用和未处理异常路径的日志 canary 扫描未发现私人载荷。数据库失败日志仅含事件、稳定错误码、命令名和关联 ID。
- 外部 `FinanceError` 未暴露 SQL、驱动原文、表列名或堆栈。
- 审计与业务写入同事务；注入失败后收据、交易头、分录和审计均回滚，使用同来源 ID 可正常重试一次。
