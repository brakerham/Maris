## 1. 范围与判定

本矩阵独立验证 P2-A 的五个查询工具与写候选工具 `finance_record_expense`、可信上下文、支出候选状态机、来源幂等、一次一写、恢复、权限、模型与数据库故障、FastAPI run/resume/status、隐私、微信安全降级和 P1 财务结果一致性。测试设计与 P2-B4 实现并行，不能以执行方测试代替独立证据。

统一状态只有以下三类：

- `通过`：在指定环境实际执行，全部预期成立并保存可复现证据。
- `失败`：任一预期不成立，记录最小输入、预期、实际、版本、环境和脱敏证据。
- `设计完成/未执行`：案例可执行但尚未绑定 P2-B4 稳定快照，或指定环境尚未具备；不得解释为通过。

P2-C6 已取得本地 SS/HTTP 证据。PG-C7-DATA-R2 绑定修复快照后，P1 原 8 项和 P2 SPG 4 项全部通过；相邻 SQLite 幂等/错误契约 9 项通过。WX-01～05、LIVE-01～03、DSK-01～03 及 HTTP-09 真实回环仍未执行；不得用 PostgreSQL 证据外推这些环境。

## 15. P2 独立执行入口

后续独立执行任务开始前必须满足：

1. P2-B4 提交不可变快照、运行说明、迁移链、执行方测试结果和文件清单，并停止修改验收文件。
2. 六个工具、Agent 应用服务、pending 状态、FastAPI 端点和测试替换点可导入；脚本化模型能确定地产生查询、候选、坏参数、未知工具、重复调用、空响应和异常。
3. 提供隔离 SQLite 夹具、虚拟时钟、可重启应用入口、事务/模型/日志可观察点和全虚拟财务数据。
4. `SS`/`HTTP` 案例是 P2-A 的本地门禁。`SPG`、`DS`、`DESK`、`WX` 只有在对应环境和总控授权具备时执行，未具备时逐项保持未执行，不能用替身冒充。
5. OpenClaw 安全暂停解除前不得执行 `WX`；没有稳定微信事件 ID 时，即使 WX 候选确认通过，也不得宣称原消息级幂等完成。

执行时先跑独立定向套件，再在一次最终项目回归中统一复跑执行方测试；两者分开统计。失败报告必须包含 ID、严重级别、最小复现、预期、实际、影响范围和脱敏证据。修复后只复跑原失败、相邻状态和必要回归。
