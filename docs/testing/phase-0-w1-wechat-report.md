本轮已证明两个执行层级：确定性微信命令与 OpenClaw 自然语言工具选择都能调用 Python 探针，并把现场生成的结果返回手机。该结论不扩展到普通文本收发、微信来源事件级幂等、完整财务 Agent、提醒或手机通知。

## 4. W-02 证据链与判定

测试输入：用户从手机微信发送 `/finance-probe V001`。

| 观察层 | 脱敏证据 |
| --- | --- |
| Python 后端 | 观察到 `POST /api/v1/probes`，HTTP 200 |
| OpenClaw | 脱敏事件记录出站发送成功；关联字段与手机实收一致 |
| 手机微信实收 | `request_id=227f230c-100c-4132-bf97-05529508a343`；`receipt=POC-987812fb5997b36aa6a608fe`；`created_at=2026-09-15T19:58:30.933208+08:00`；`replayed=false` |
| 跨层一致性 | OpenClaw 脱敏事件中的 `request_id`、`receipt`、`replayed` 与手机实收完全一致 |

判定：**通过**。

理由：请求实际到达 Python 端点并成功返回；后端生成的请求编号和回执穿过 OpenClaw 出站链路抵达手机，关键关联字段一致，排除了仅在手机端固定回复“调用成功”的情况。`created_at` 带 `+08:00` 时区，`replayed=false` 与首次调用相符。

证据限制：本案例只有一次首次调用，不能据此通过 W-03 或证明重放行为；OpenClaw 2026.8.2 命令上下文没有微信来源事件 ID，因此也不能据此宣称微信事件级幂等。当前交接未包含独立的普通收发案例，W-01 保持未测。

## 5. W-04 停服证据链与判定

测试输入：Python 探针停止后，用户从现有手机微信会话发送 `/finance-probe V002`。

| 观察层 | 脱敏证据 |
| --- | --- |
| 后端状态 | 健康端点不可达 |
| OpenClaw 入站 | 2026-09-15 20:07:57 收到命令 |
| 桥接失败 | 20:07:58 记录 `finance_probe_failed`、`code=backend_unavailable`、`retryable=true`、`duration_ms=2` |
| 成功结果否定证据 | 未生成 request ID 或 receipt |
| OpenClaw 出站 | 脱敏记录显示错误消息发送成功 |
| 手机微信实收 | `backend_unavailable: The probe service is unavailable.` |

判定：**通过**。

理由：后端确实不可达时，桥接返回稳定、明确且可重试的服务不可用错误，并将该错误成功送达手机；没有生成成功关联字段，没有复用 W-02 的 receipt，也没有声称调用成功。

编号说明：总协调将其描述为后续停服结果；依据 `docs/testing/phase-0-test-matrix.md`，停服场景正式归入 W-04。W-03 是“再发送一次新的成功探针并得到新的 request ID/receipt”，本次停服失败不能替代该案例，故 W-03 仍为 `未测`。
