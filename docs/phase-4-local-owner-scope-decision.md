# P4 本地单主人范围决定

- 决定时间：2026-09-26 16:49，Asia/Shanghai
- 决定者：用户与头脑风暴总控
- 状态：`accepted`，作为后续 P4 产品范围依据

## 1. 用户场景

当前产品首先服务用户本人：Windows 电脑运行桌面应用和本地后端，手机通过微信消息进入同一套个人数据。用户目前没有用于托管账户和个人财务数据的服务器，也不计划让其他人登录用户自己的主机。

如果其他人以后使用这个项目，默认方式是每个人在自己的设备上安装自己的实例、保存自己的数据库和密钥，不连接到用户的电脑，也不共享用户的账户。

## 2. 当前代码的实际能力

P4-A 已实现的身份能力是“每个安装实例一个 bootstrap owner”，不是公开多用户平台：

- migration 创建一个 `pending_setup` 的 singleton owner；
- `/auth/initialize` 只允许 loopback、bootstrap token 和未初始化 owner，且只能成功一次；
- 已有密码登录、access/refresh token、设备 session、撤销和微信渠道绑定的后端能力；
- P4-IF-001 已明确不提供公众注册、找回密码或管理员创建第二用户；
- `user_id`、Principal 和复合外键用于保证业务事实、Agent 运行、记忆、工具和微信身份不会跨作用域串写。

这些后端能力尚未形成桌面端登录界面，整个 P4-A 也尚未经过 C11 独立验收。

## 3. 采用范围

从本决定开始，近期产品范围固定为：

```text
单机部署
+ 单主人
+ 本地数据库
+ Windows 桌面完整交互
+ 微信作为同一主人的手机消息入口
```

近期暂停：

- 公众注册；
- 第二本地用户或管理员创建用户；
- 多租户服务器；
- 云端账户中心；
- 跨主机登录；
- 面向用户的注册页面和常规登录页面；
- 找回密码、邮箱/手机验证码、邀请和组织账户。

“暂停”表示不继续扩展、不制作 UI、不为这些能力增加新需求。现有后端代码和数据库结构暂时保留，不在 P4-B6-R2-S1、S2 或 C11 前执行删除或重写。

## 4. 保留的内部身份边界

以下内容继续作为本地 Personal AI Host 的安全基础：

- 每条业务数据的可信 `user_id`；
- `PrincipalContext` 与工具权限；
- 不接受 API、模型或工具参数伪造 owner/user；
- 财务、记忆、会话、Agent run 和 pending action 的 user scope；
- 微信/OpenClaw 外部身份到本地 owner 的显式绑定；
- 本地 API 的可信客户端/session 边界；
- token、密钥、密码和真实身份不进入模型、普通日志和 receipt。

保留这些结构不代表产品提供多用户服务。单主人也需要稳定的内部 owner ID，才能让不同模块、桌面端和微信端访问同一份数据，并防止不可信消息或工具调用指定任意数据所有者。

## 5. 为什么当前不删除认证实现

现在删除认证和 user scope 会同时改动三个 P4 migration、Host API、Principal、微信绑定、活动导入、Finance、Agent、memory、receipt、执行方测试和 C11 矩阵。R1 已修复的一次性绑定、session、token 隐私和跨用户约束也会失去基线。

保留这些表和代码不会要求部署服务器，也不会把数据上传到别人的主机。它们随本地后端运行，数据库仍位于用户自己的设备。当前更有效的做法是停止继续扩展账号产品功能，把开发资源用于财务功能、Agent、桌面界面、毛毛、财富管理和数据可视化。

## 6. 桌面端以后需要裁定的入口

桌面 Shell 开始实现前，再从以下本地入口中选择一个；本决定不提前实现：

1. **本地 owner 自动会话**：安装时建立 singleton owner，由 Electron main 使用 Windows 安全存储持有本地凭据，普通启动不显示登录页。
2. **可选应用锁**：默认单主人，用户可选择 PIN、密码或系统解锁，用于同一台电脑被他人接触时保护财务数据。
3. **显式登录**：只有确认需要远程访问、多 Windows 用户共享同一实例或部署服务器时才启用完整登录界面。

无论选择哪种入口，renderer 都不能直接获得数据库密钥、长期 token 或 bootstrap secret。

## 7. 重新评估触发条件

只有出现以下实际需求之一，才重新让技术顾问评估账户方案：

- 用户需要跨电脑同步；
- 手机不再通过本机微信桥接，而要直接访问远端服务；
- 同一安装实例确实要服务多个人；
- 项目要公开部署成托管服务；
- 需要家庭共享、组织空间或协作预算；
- Windows 本地自动会话无法满足设备丢失、共享电脑或隐私要求。

重新评估时再比较本地系统账户、端到端加密同步、自托管服务器和云端账户。当前不购买服务器，也不为假设中的多用户提前建设注册系统。

## 8. 对当前流水线的影响

- `P4-B6-R2-S1` 不变：它只补 module/Profile version 和 memory invalidated，不修改 auth。
- `P4-B6-R2-S2` 仍执行 PostgreSQL 迁移与安全回归，因为现有身份边界保护本地数据和微信绑定。
- `P4-C11` 仍验收已有 bootstrap owner、session、binding 和 user scope，确保保留下来的本地安全基础可靠；不增加公开注册、多用户或登录 UI 用例。
- P4 桌面 UI 不实现注册和常规登录页面；桌面入口在 Shell 开始前按第 6 节另行裁定。
